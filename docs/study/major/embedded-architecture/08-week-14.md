# 14주차: 인터럽트, 고성능 컴퓨팅 시스템 구조

작성일 2023-06-07 · 최종 수정일 2023-06-13
{ .post-date }

- 하드웨어 장치의 충돌

    - 두 개 이상의 장치가 버스를 차지하려고 하면 충돌이 발생할 수 있음.

- I/O 버스의 충돌

    - I/O 장치들이 같은 자원(특정 I/O 주소, 특정 IRQ 번호, 특정 DMA 채널)을 동시에 차지하려면 충돌 [IRQ : 인터럽트 번호]

        - I/O 주소 충돌 ⇒ 전송될 I/O 주소가 중복
        - IRQ 번호 충돌 ⇒ 인터럽트 컨트롤러와 충돌
        - DMA 채널 충돌 ⇒ DMA 컨트롤러와 충돌

- 충돌의 방지(두 가지 방법으로 충돌 방지 가능)

    - IRQ 공유(shared IRQ 허용)

        - 한정된 IRQ를 공유하도록 I/O 버스 컨트롤러가 허용

    - 지능적인 `버스 마스터링`

        - 버스 컨트롤러가 매우 지능적이라 CPU와 다른 별개의 프로세서처럼 동작, CPU가 전송에 개입하지 않게 된다.

- PnP(Plug & Play)

- 버스 사이클(Bus Cycle)

    - 버스를 이용해 메모리나 I/O 장치에서 데이터를 읽거나 쓰기 위해 반복적으로 수행해야 하는 일련의 연속 동작.

        - 동기식 버스 : 시스템 버스 클럭에 동기되어 동작결정
        - 비동기식 버스 : 다른 신호의 발생 여부로 동작결정

- 동기식 버스 

    - 메모리나 I/O 장치의 로컬버스가 시스템 버스의 클럭에 동기를 맞춤. (예를 들어, 메인 메모리에서 데이터를 빼오는 것이 시스템 버스 클럭에 맞춰지는 경우로 보인다.)

        - 구조가 간단해서 하드웨어 설계가 간단하고 정확해서 고속 및 고성능 컴퓨터 시스템을 설계하기가 용이하다.

    - 느린 소자를 대비해서 추가적인 대기 클럭을 추가할 수 있음.

        - H/W 마다 동작 속도가 다를 수 있기 때문이다.

- 비동기식 버스

    - 처리 순서를 설계하기가 다소 복잡하지만, 고성능 컴퓨터 시스템을 설계하기에는 동기식 버스에 비해 다소 어려워진다.

    - 읽기 동작의 설계

        - 마스터 → 읽기 데이터 신호 내보냄
        - 슬레이브 동기 신호를 내보내 보고

    - 쓰기 동작의 설계

- 버스 컨트롤러

    - PCI 이후 요즘의 I/O 버스 컨트롤러
    - 어떤 I/O 장치가 일단 버스 마스터가 되면 버스를 제어하고 시스템 메모리에 대해 읽고 쓰기를 요청

- 버스 마스터링

    - 완화, Balancing에 대한 연구가 진행되는 것으로 보인다.

    - 주변장치가 CPU의 간섭을 받지 않고 독자적으로 메모리와 I/O 장치 사이에 데이터를 전송할 수 있도록 해주는 버스 설계 기술

        - I/O 장치와 메모리 사이에 데이터 전송이 이루어지는 동안 CPU가 다른 작업을 할 수 있어 다중작업에 유리하다.

    - 버스 마스터

        - 버스를 직접 제어, 점유해 사용하는 주체
        - 버스 마스터와 다른 입출력 장치와의 관계는 Hierarchical, 마스터(master)와 슬레이브(slave)의 주종관계

    - `버스 중재`(Bus Arbitration)

        - 버스 마스터 간에 일어나는 버스 경합 문제를 조정한다.(서로 차지하려고 하는 경우)

            - 버스 요청 신호
            - 버스 사용 중 신호
            - 버스 승인 신호

    - 버스 중재기(bus arbiter) ⇒ 버스 컨트롤러가 역할한다.

#### 인터럽트(interrupt)

- 인터럽트가 발생하면 **인터럽트 서비스 루틴**(ISR)을 수행하게 된다.

    - `인터럽트 폭풍`(interrupt storm) : 인터럽트 처리 시간이 과도해 시스템 성능에 심각하게 방해를 하는 현상

- 이전에 IRQ 번호가 있다고 했는데, IRQ는 여러 개가 Table 상에 존재하고 각각이 담당하는 역할이 나뉘어져 있다.

    - 컴퓨터 입장에서 interrupt는 반드시 수행해야 하는 현상이기 때문에, interrupt storm을 과도하게 유발시키는 공격 형태도 있다.

- interrupt의 종류

    - H/W 인터럽트
    - S/W 인터럽트(trap) : Operation 관련해 특정한 에러가 발생하거나, 의도적으로 interrupt를 발생시킨 경우.

    - H/W 인터럽트

        - 주로 CPU 외부 장치의 요청에 의해 발생
        - 비동기적 interrupt이다. (trap은 동기적)

    - 막을 수 있는 인터럽트(maskable interrupt) : IRQ 사용
    - 막을 수 없는 인터럽트(non-maskable interrupt, NMI) : ex. turn down

- interrupt의 제어 신호

    - 인터럽트 요청(IRQ) 신호

        - 인터럽트 발생시 I/O 장치가 CPU에 버스 사용을 요청

    - 인터럽트 확인(interrupt acknowledge, INTA) 신호

        - CPU가 외부 장치에 인터럽트 요청 접수를 알림 ⇒ 인터럽트 전달을 확인함.

    - 인터럽트 컨트롤러는 외부 인터럽트 신호를 전달받고 비동기적인 처리를 지원함.

- 인터럽트 제어 방식

    - 병렬식 연결이 가장 빠르고 좋은 방식.
    - 각 I/O 장치마다 별도의 **IRQ** 선과 **INTA** 선이 존재하게 됨.

- `병렬식 인터럽트`**의 처리 방식**

    - 주변장치가 CPU에 인터럽트 요청 IRQ 신호를 보냄
    - CPU에서 현재 작업 내용을 저장
    - CPU가 인터럽트 처리
    - CPU가 주변장치에 인터럽트 확인 INTA 신호 보냄
    - INTA 신호를 받은 주변 장치는 IRQ 신호를 삭제
    - CPU가 본래의 상태로 복귀

- `직렬식 인터럽트 제어`

    - **하나의 IRQ 신호선과 하나의 INTA 신호선 공동 사용**

- **직렬식 인터럽트의 처리 방식**

    - 주변장치가 CPU에 인터럽트 요청 IRQ 신호를 보냄
    - CPU가 IRQ를 보낸 장치 조사를 위해 INTA 신호를 보냄. (식별 필요해서)
    - 해당 장치가 I/O 버스로 인터럽트 벡터 ID 보냄
    - CPU가 현재 작업 내용을 저장
    - CPU가 인터럽트를 처리
    - CPU가 본래의 상태로 복귀

- 소프트웨어 폴링 방식 인터럽트 제어

    - 하나의 IRQ 신호선만 공동으로 사용

        - 시간은 많이 걸리나 인터럽트 검사 주기와 우선순위를 가변시킬 수 있어 편리

#### 8장 : 고성능 컴퓨팅 시스템 구조

- `병렬처리`(parallel processing)

    - 다수의 프로세서들이 여러 개의 프로그램들 혹은 한 프로그램의 분할된 부분들을 분담하여 동시에 처리하는 기술
    - 병렬처리의 목적은 여러 작업을 사용자가 동시에 처리된다고 느낄 수 있도록, 최대한 동시에 수행하는 것이다.
    - 한 프로그램을 여러 개의 작은 부분들로 분할하고, 분할된 부분들을 병렬로 처리한 결과가 전체 프로그램을 순차적으로 처리한 경우와 동일한 결과를 얻을 수 있어야 함.

- 야기되는 새로운 문제들

    - 문제 분할(problem partition) : 병렬 처리를 위해 문제를 여러 개로 나누는 것.
    - …

- 병렬 처리의 단위

    - 작업-단위 병렬성(Job-level parallelism) 
    - 태스크-단위 병렬성 : 하나의 큰 작업을 기능에 따라 분할한 작은 프로그램(태스크) 단위로 처리하게 된다.
    - 스레드-단위 병렬성 : 동시에 처리될 수 있는 가장 작은 크기의 독립적인 단위
    - 명령어-단위 병렬성 : 데이터 의존성이 존재하지 않는 여러 개의 명령어들을 동시에 수행하는 병렬처리

- Flynn의 분류

    - 구조적 특징에 따른 컴퓨터 분류 방식

        - 명령어 스트림(instruction stream) : 프로세서에 의해 실행되기 위하여 순서대로 나열된 명령어 코드들의 집합
        - 데이터 스트림(data stream) : 그 명령어들을 실행하는데 필요한 순서대로 나열된 데이터들의 집합

        - 단일 명령어 스트림 - 단일 데이터 스트림 (SISD)

            - CU → (IS) PU(Processing Unit) → (DS) MM(Memory Module)

        - 단일 명령어 스트림 - 복수 데이터 스트림 (SIMD)

            - 여러 개의 프로세싱 유닛(PU)으로 구성되고, 프로세싱 유닛(PU)들의 동작은 모두 하나의 제어 유닛(CU)으로 통제된다.

        - 복수 명령어 스트림 - 단일 데이터 스트림 (MISD)

            - N개의 프로세서들이 서로 다른 명령어들을 실행하지만, 처리하는 데이터 스트림은 한 개 → 비현실적이므로 실제 구현된 경우는 없었음.

        - 복수 명령어 스트림 - 복수 데이터 스트림 (MIMD)

            - N개의 프로세서들이 서로 다른 명령어들과 데이터들을 처리

                - 밀결합 시스템(**tightly-coupled system**)
                - 소결합 시스템(**loosely-coupled system**)

- 기억장치 액세스 모델에 따른 분류

    - 균일 기억장치 액세스(Uniform Memory Access : UMA)

        - 모든 프로세서들이 상호연결망에 의해 접속된 주기억장치를 공유한다.
        - 모든 프로세서들이 주기억장치의 어느 영역이든 액세스 할 수 있음.
        - 장점 : 하드웨어가 간단하고, 프로그래밍이 용이하다.
        - 단점 : 공유 자원에 대한 경합이 지속적으로 발생. 시스템 확장에 한계가 있다.

    - 불균일 기억장치 액세스(Non-uniform Memory Access : NUMA)

        - UMA 모델의 한계를 극복해 더 큰 규모의 시스템을 구성하기 위한 모델

    - 비-원격 기억장치 액세스(No-remote Memory Access : NORMA)

        - 분산-기억장치 시스템(distributed-memory)

- SMP

    - **프로세서들이 시스템 내의 모든 자원들을 공유**함

    - symmetric

        - 모든 프로세서들이 필요 시 직접 OS 코드를 수행
        - 모든 프로세서들이 **자원들을 동등한 권한으로 사용**

    - 시스템 버스로 모든 프로세스와 메모리, I/O에 대한 입/출력으로 모두 처리되는 구조

- 대규모 병렬프로세서(MPP)

    - 대규모 병렬처리 시스템이나, **무공유 구조(shared-nothing)를 기반으로 함.**

- 캐시-일관성(Cache-Coherent) NUMA

    - S/W 변경 없이 SMP보다 더 큰 시스템을 구축할 때 유지 가능

- 분산 시스템(오래된 topic)

    - **독립적인 노드(컴퓨터 시스템)들이 전통적인 네트워크에 의해 접속**
    - 중앙 집중 시스템은 책임자가 한 명이지만, 분산 시스템은 다수가 책임이 있는 시스템

- 클러스터 컴퓨터(고전적 classical한 분류)

    - 클러스터링, Grouping 같은 표현
    - 클러스터는 특정한 기능, 목적, 역할들을 위해서 그룹을 묶는 것. 여러 개가 존재할 수 있으며, 컴퓨터에서도 비슷한 개념으로 사용됨.
    - 대체로 클러스터는 그 사이에서 헤드를 뽑는다.

- 다중프로세서시스템 구조(Multiprocessor system architecture)

    - 기억장치 모듈을 사용하는 (소유하는) 구조에 따라 나눠짐.

- 밀결합 시스템의 장점

    - 프로세서간 데이터 교환 메커니즘이 필요하지 않음.
    - 프로세서들과 기억장치들 간의 통로(버스 또는 상호 연결망) 상에 통신량이 많아지기 때문에 경합으로 인한 지연 시간이 길어질 수 있음.

- 공유-버스 구조

    - 성능 저하 가능. (Shared Line은 경합이 발생하면 유난히 느려질 수 있음)

- 다중-버스 구조

    - 경합을 줄이고자 버스의 개수를 늘림

- 크로스바 스위치

- 다단계 상호연결망(MIN)

    - 크로스바 스위치의 단점을 없애기 위한 것으로 보인다.
