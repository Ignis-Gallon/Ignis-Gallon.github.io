# 13주차: Paging

## Memory Management

- RAM 관리 (contiguous allocation은 시작과 끝을 나타내는 H/W를 도입, Base and Limit Register 사용)

    - 그러나 Contiguous Allocation은 Fragmentation이 발생한다는 문제가 있었음.

        - External Fragmentation
        - Internal Fragmentation

    - 그리고 Hole을 만들기 위해 H/W 자원을 사용, 낭비가 발생하게 됨.

- 이에 따라 기존의 전제인 Contiguous Allocation을 배제하고, Paging을 도입함.

---

## Paging

- 실제 물리주소를 가상주소로 연결해서, 실제로는 연속적이지 않지만 유저와 프로세스, CPU는 연속적으로 할당된 주소를 사용하고 있는 것처럼 보이게 만드는 것.

    - Physical Address : Non-contiguous
    - Logical Address : Contiguous

- Paging을 이용하면 External Fragmentation은 방지할 수 있지만, Internal Fragmentation은 어쩔 수 없이 발생하게 된다.

ex) 1000번지에서 데이터를 가져온다고 할 때, [ p | d ] 형태의 데이터가 필요하다. 이때 p는 page index를 말하며, d는 변위, offset이다. 이 데이터를 physical Address로 변경하게 된다.

[ f | d ], f : frame, d : 이전에 가져온 offset.

그렇다면, 어떻게 [ p | d ] 를 [ f | d ]로 변경할 수 있을까?

- CPU가 작업을 수행할 때 필요한 데이터를 Logical Memory에서 찾아 요청한다. 이 정보는 Page Table을 거쳐 실제 Frame(물리주소)으로 변환되고, 물리주소에서 해당되는 frame에서 데이터를 가져와 전달해주게 된다.

    - 이와 같은 방법을 통해 CPU 입장에서는 중간에 변환해주는 Page Table이 있다면, 실제 Physical Memory에서 contiguous allocation을 하지 않아도 프로세스를 잘 할당할 수 있게 된다. (Fragmentation 방지, Compaction 방지)

- Logical Size = 2^m, Page Size = 2^n

전체 크기가 8이라고 할 때, 만약 n = 2라면 한 페이지 안에 데이터를 네 개 넣는다.  
⇒ 왜냐면, 2^2 = 4이고, 이것이 Page의 크기이기 때문.

m = 8이라면, 네 개 짜리 page를 갖는 page가 2^6개 존재할 수 있다.  
⇒ 2^(m-n) = 2^6이므로, 네 개의 데이터를 갖는 page가 2^6개 존재할 수 있게 되는 것.

ex) logical memory에서 m - n = 2이고, m, n을 모른다고 해보자.

우선 m-n = 2이라는 것은, 페이지의 개수가 4개라는 것이다. (2^2 = 4)

여기서 n이 2라면, 오프셋 주소가 네 개씩 있다는 것(즉, 한 페이지당 네 개의 데이터)

m - n = 2이고, n = 2이기 때문에 m = 4.

> Physical Memory는 일반적으로 Logical Memory보다 작을 수밖에 없기 때문에, 가상메모리까지 연결된다.

ex) Page Size = 2048 bytes.

Process Size = 72,766 bytes.

계산해보면, 하나의 프로세스를 표현하기 위해서 35 pages + 1,086 bytes가 필요하게 되고, 따라서 총 36 개의 pages가 필요하게 된다.

평균적인 Internal Fragmentation의 크기는 1/2 frame size.

그렇다면, 어쩔 수 없이 생기는 이 Internal Fragmentation의 크기를 줄이려면 어떻게 해야 할까?  
⇒ Page의 크기를 줄여야만 하는 것이다.

그런데, Page의 크기가 무조건 작아지면, Page Tables가 커지고, Page가 너무 크면 Internal Fragmentation의 크기가 커지게 된다.

- Free Frames(할당되지 않은 프레임, 가용 프레임)

⇒ **운영체제는 각 프로세스마다 페이지 테이블을 개별적으로 유지해야 한다.**
