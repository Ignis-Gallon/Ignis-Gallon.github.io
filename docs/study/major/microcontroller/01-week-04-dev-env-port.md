# 4주차: 개발 환경, PORT 제어

작성일 2022-09-26 · 최종 수정일 2022-10-09
{ .post-date }

## \# `개발 환경에 익숙해지기`

- `포트 제어`

    - 가장 쉽게 제어할 수 있는 것이 PORT이다.
    - Alternative Function으로 사용하지 않고, PORT로 다 써도 괜찮다.

- `PORT로 무엇을 할 수 있는가?`

    - 실습에 사용할 포트는 C포트 (PC0 ~ PC7 핀 사용)
    - 보드의 사이드에 있는 컨넥터들은 포트로 연결된 것들이다.
    - 라인에는 라인의 이름과 번호가 부여되어 있다. (회로도 기준으로) 초록색으로 써있는 숫자는 실제 보드에 적용되는 컨넥터의 번호이다. (회로도와 보드의 번호를 Mapping해서 본다.)

    - PORT를 가지고 내가 제어를 할 수 있다. HIGH or LOW → by S/W  
        → CPU의 가장 훌륭한 기능 : S/W 명령에 의해서 해당하는 포트를 물리적으로 반영하여 전기적으로 조절할 수 있다. (S/W로 H/W를 물리, 전기적으로 조절하여 연산하고 동작시킨다.)

        → 이러한 것을 OUTPUT으로 볼 수 있으며, INPUT도 가능하다.  
        PC0에 연결된 선이 HIGH인지 LOW인지를 CPU 기준에서, INPUT으로 읽어들일 수 있다.  
        즉, 한 개의 PORT로 INPUT과 OUTPUT이 가능하다는 것이다.

        → 그런데, 입출력은 동시에 불가능하다. 내가 원할때 맘대로 바꿀 수 있는 것이 아니라, CPU에게 현재 입력으로 쓸 것인지 아웃풋으로 쓸 것인지를 알려줘야 한다.

        → 일반적으로 출력을 할 때 쓰는 포트는 C이다. (초기값은 0)

    - PORT 바이트에 비트 별로 쓰는 값이 PORT에 반영되는데, 그 전에 입출력을 정의해준다.

        → 즉, Data의 Direction을 정해줘야한다. (DDR, Data Direction Register)

        → 각각의 포트 별로 DDR이 따로 존재한다.

        → 똑같은 포트 C라고 하더라도 아랫쪽 네 개는 출력으로, 위쪽 네 개는 입력으로 가능하다.  
        즉, 비트 별로 입출력 제어가 가능하다. (reset value는 0 : 즉, 기본 값은 입력이다.)

    - 입력을 받을 때는 PORTX 가 아닌, PINX (이번 예제에서는 C)를 사용한다.
    - 입력이 어떻게 되는지를 확인하려면, 선언한 변수를 기준으로 입력을 확인하는 것으로 보인다.
    - 8 bit를 확인하려면 어떻게 해야되는가? → char를 사용한다. 그런데, unsigned를 사용.  
        → why? char는 상위 비트가 부호 비트이기 때문에 register와 관련된 변수를 사용하거나  
        어떤 변수의 값을 넣는다면 반드시 unsigned를 사용해야 한다. 즉, unsigned char를 선언.
    - unsigned bit를 선언하고 PINC에서 값을 읽어들이면, 현재 H/W적으로 선언된 PIN으로 들어오는 레벨을 Level을 확인해줄 수 있다. (HIGH or LOW) → DDR도 반드시 선언 필요! DDR → 1

- `Ex)` 비트별로 만약 포트C의 3번 비트 값을 읽어 들여 led3 라는 비트 값에 할당하려면

```c
led3 = (PINC & 0x08);
```

→ PINC의 선에 연결된 Level이 0이냐 1이냐를 결정할 수 있는 코드!

→ 그러나 이를 하기 전에 DDR을 INPUT으로 정해줘야 한다.

- `연결`

    - Light Emission Diode(LED) → 0.7V 이상만 통과시켜준다.  
        Anode(긴 쪽, +) Cathode(짧은 쪽, -) 차이의 전압 차가 0.7V 이상이어야만 통과시킨다.
    - 0.7V 이상일 때 동작한다는 뜻은? → LED의 불이 켜진다, 전압차가 클수록 빛이 밝아진다.
    - 그런데, 회로에 저항을 추가로 달아주는 이유는, 저항이 없으면 LED가 켜지지 않기 때문이다.  
        선 자체에 저항이 있기는 하지만, 무시할만 하다. 저항이 없으면 불이 켜지지 않는다. I = V/R 이기 때문에 저항 값이 작은 저항을 달아줘서 LED가 동작할 수 있도록 한다.
    - PORT를 LOW를 줘야 전압차가 발생하기 때문에, PORT에 LOW를 줘야 전압차가 발생하기 때문에 LED가 켜진다. 반대로 LED를 끄려면 HIGH를 줘서 전압차를 없앤다.

```c
#include <avr/io.h>

int main(void)
{
	DDRC = 0x01; // 포트 C의 첫 번째 비트를 출력 핀으로 사용(출력이 1)
	PORTC = 0xFE; // 첫 번째 비트에 logic low -> LED ON
}
```

→ 기본 C 프로그래밍에서는 `#include <stdio.h>` 를 했지만, 이는 키보드로부터 stdin을 받고 모니터 터미널을 통해서 stdout을 내보내기 위해 선언한 것이고, 마이크로컨트롤러 프로그래밍은 선언하는 라이브러리가 다르다.

> `#include <avr/io.h>`  
>
> \#elif defined (\_\_AVR_ATmega2560\_\_)  
> \# include &lt;avr/iom2560.h&gt;  
>
> → 모든 코드가 이렇게 이루어져 있음.  
> io.h는… AVR에서 다양한 MCU가 있는데, 거기서 Target MCU를 설정하고 그 MCU에 맞게 Project를 설정할 건데, Target MCU를 설정하면 자동으로 어떤 CPU를 쓰는지를 알려준다. 그렇게 되면 어떤 것을 include할 지가 선언되는 것이다.  
>
> iom2560.h에는 코드에 사용할 수 있는 모든 Register들이 정의되어 있다.  
> 우리가 코드에서 DDRC, PORTC 등을 사용할 수 있는 것은, 이미 라이브러리에 선언되어 있기 때문에 사용할 수 있는 것이다.
