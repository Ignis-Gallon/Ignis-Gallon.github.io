# 9주차: 리소스 추가, 액자형 UI

## &lt;수업(2024-04-30, 화)&gt;

### Resource(그림) 추가하기

Solution에 들어가면 res 폴더가 있는데, 해당 폴더에 이미지를 복사해서 넣으면 된다. 그러면 나중에 실행 파일 안에 resource가 포함되어 사용할 수 있게 된다.

- WidthRequest, HeightRequest

    &lt;image&gt;의 WidthRequest, HeightRequest는 이미지의 크기를 바꾸는게 아니라 이미지를 그릴 공간의 크기를 바꾸는 것이다. 그림은 고유 사이즈에 맞춰 그려진다.  
    ⇒ 따라서 만약 50x100으로 Request를 설정할 때, 이미지가 1:1비율이라면 50x50으로 그려진다.

- StackLayout 안에 AbsoluteLayout을 넣기

    - 만약 AbsoluteLayout 안에서 Image의 좌표를 0,0,300,300으로 한다면, AbsoluteLayout은 StackLayout을 기준으로 좌표를 결정할까, 아니면 전체를 기준으로 결정할까?

        > Nested AbsoluteLayout은 View요소의 크기를 할당받는다. 따라서 StackLayout 내부에 위치할 경우, 화면 전체가 아닌 StackLayout의 크기를 할당받는다.

    > 좌표 설정 방식 x,y,a,b  
    > ⇒ (x, y)를 시작으로, 가로 세로 a, b 크기 만큼 그리는 것.

- 크기를 매우 크게 하면, 한 화면에 모든 View 요소가 나오지 못하고 아래로 넘칠 수도 있다.
- AbsoluteLayout은 서로 겹쳐진다.

### 액자형 UI 구성

원래 이미지 사이즈에 맞춰서 검은색 BoxView를 만들고, 그 위에 Absolute Layout으로 올린다.

## &lt;C# 강의&gt;

### 절차지향과 객체지향

- **절차지향**: 컴퓨터의 데이터 처리 순서에 따라 프로그래밍을 하는 방식. 그런데 만약 스레드를 여러 개 사용하면 절차지향이라고 하더라도 처리 순서는 조금씩 달라질 수 있다.

- **객체지향**: 데이터와 그 데이터를 처리하는 함수인 메서드를 동시에 갖는 객체를 중심으로 프로그램을 구성하는 방식. 객체 간의 관계를 정의해 놓으면, 이후에 시작점에 데이터를 던져줄 때 정해진 관계나 순서에 따라서 동작하게 된다.

    ⇒ 객체의 순서와 관계를 잘 정리하는 것이 중요하다.

> 함수를 짧고 여러 개 만들라고 하지만, 실제로는 함수를 많이 사용하면 비효율성이 증가한다. 그래서 그것이 꼭 효율적이지는 않고, 역시 클래스를 많이 만든다고 해서 항상 효율적이지는 않을 수도 있다. 그럼에도 객체와 함수를 최소 단위로 만들어 모듈화 하는 것이 개발을 편리하게 만들어주기 때문에 이를 통해 효율성을 얻게 된다.

- **상속:** Inheritance
- **캡슐화:** Information Hiding
