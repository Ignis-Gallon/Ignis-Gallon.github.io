# Dart 1: Why Dart?

작성일 2023-02-15
{ .post-date }

- dart는 두 개의 컴파일러가 있음.

    - dart Web : 내가 작성한 dart 코드를 JS로 변환해주는 컴파일러
    - dart native : 내가 작성한 dart 코드를 여러 CPU의 아키텍쳐에 맞게 변환한다.

    ⇒ ex) ARM32, ARM64, Desktop

    그러므로, d를 쓰는 것 만으로 iOS, Android, Windows, Linux, Mac으로 컴파일이 가능해진다. 뿐만 아니라 더 작은 전력의 아키텍쳐로도 가능하며, 따라서 flutter로 사물인터넷 개발도 진행할 수 있다.

- just-in-time, ahead-of-time

    - AHT : 코딩을 다하면, 컴파일 할 때 아키텍쳐를 지정해주어야 한다. 예를 들어 C++로 코딩했을 때 Windows에 배포하고 싶다면 Windows 바이너리로 컴파일해야 한다. 즉, 컴파일을 먼저하고, 그 결과인 바이너리를 배포하는 것이다. 이는 최적화하는데 많은 시간을 소요하게 되고, 코드를 기계어로 바꿔야 하는 등 하는 일이 많기 때문에 UI를 만들고 있다면 이건 최적의 방법이 아니다.

        예를 들어, UI를 개발하고 있는데 버튼을 수정하고 싶다고 생각해보자. 그러면 뭔가를 변경할 때마다 그 결과를 보고 싶으면 컴파일을 진행해야 한다. 개발 중에는 빨리 반복할 수 있는 것이 중요하므로 개발 경험이 좋지 못하다.

    - JIT : dart VM을 사용하여 내가 쓴 코드의 결과를 화면에 바로 보여준다. 이는 내 코드가 가상 머신에서 작동하고 있는 것이기 때문에 조금 느리지만, 이는 개발 중에만 사용되므로 괜찮다. 따라서, 배포할 때는 JIT를 이용해 바이너리로 배포하기 때문에 속도의 문제가 없다.

- null safety : 안전한 프로그램을 빌드할 때 굉장히 중요한 특성이다. null을 참조해버리면 프로그램이 고장나 버리는데, dart는 null safety를 채용해서 프로그램을 안전하게 만들었다.

flutter는 왜 dart를 택했을까? 첫 번째로, JIT와 AHT이 모두 있기 때문이다. 이 것은 모바일 개발에 굉장히 중요한 역할을 한다.

또 다른 점은, Dart와 flutter를 모두 구글이 만들었기 때문이다. 그러므로 flutter와 dart 모두 구글이 수정할 수 있다는 강점이 있다.
