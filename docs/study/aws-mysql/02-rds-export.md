# RDS에서 데이터를 내보내는 방법

사용 중인 AWS RDS에서 데이터를 내보내는 동안 컴퓨팅 자원의 사용을 최소화하는 것이 중요하다면, 다음 두 가지 방법이 효과적일 수 있다.

## 1. AWS DMS (Database Migration Service) 사용

- **이유**: AWS DMS는 실시간 데이터 복제를 지원하며, RDS 인스턴스에 미치는 영향을 최소화하면서 작업을 수행한다. DMS는 소스 데이터베이스의 부하를 분산시키고, 필요한 경우 데이터를 필터링하거나 변환할 수 있다.

- **장점**:

    - **저부하 복제**: DMS는 소스 데이터베이스에 높은 부하를 가하지 않으면서 데이터를 실시간으로 복제한다.
    - **연속적인 데이터 동기화**: 데이터를 마이그레이션하는 동안에도 소스 데이터베이스가 계속 사용 가능하며, 변경 사항이 지속적으로 동기화된다.
    - **유연성**: 데이터 필터링, 변환 등 다양한 옵션을 제공하여 필요한 데이터만 선택적으로 이전할 수 있다.

## 2. MySQL 덤프 사용 (부하 관리)

- **이유**: `mysqldump`는 RDS 인스턴스에서 직접 데이터를 추출할 수 있는 간단하고 표준적인 방법이지만, 옵션에 따라 RDS 인스턴스에 미치는 부하를 조절할 수 있다.

- **장점**:

    - **부하 조절**: `-single-transaction` 및 `-quick` 옵션을 사용하여 데이터베이스의 부하를 줄일 수 있다.
    - **간단한 프로세스**: 별도의 서비스 구성이 필요 없으며, 표준 MySQL 도구를 사용한다.

- **주의사항**: `mysqldump` 사용 시 데이터베이스 크기와 서버의 성능에 따라 백업에 상당한 시간이 걸릴 수 있으며, 이는 서버에 부하를 줄 수 있다.

## 선택 시 고려사항

- **데이터베이스 크기**: 매우 큰 데이터베이스의 경우, DMS가 더 효과적일 수 있다.
- **백업 윈도우**: `mysqldump`는 더 긴 백업 윈도우를 필요로 할 수 있다.
- **기술적 복잡성**: DMS는 설정이 복잡할 수 있지만, 더 많은 기능을 제공한다.
- **비용**: DMS 사용 시 **추가 비용이 발생**할 수 있다.

데이터베이스의 크기, 사용량 패턴, 운영 팀의 기술적 능력 등을 고려하여 가장 적합한 방법을 선택하는 것이 중요하다.
