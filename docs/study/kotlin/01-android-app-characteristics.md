# 안드로이드 앱 개발의 특징

## `컴포넌트를 기반으로 한 앱 개발`

- `컴포넌트` : 애플리케이션의 구성 요소

    → 컴포넌트는 애플리케이션이 아니라 애플리케이션을 구성하는 단위이다. 즉, 하나의 어플리케이션은 여러 컴포넌트로 구성된다.

    → 안드로이드의 앱의 기본 구조도 컴포넌트에 기반을 두므로, 하나의 앱은 여러 컴포넌트로 구성된다. 그리고 안드로이드에서는 클래스로 컴포넌트를 개발한다. 즉, 하나의 클래스가 하나의 컴포넌트가 되는 것이다.

    → 그러나, 모든 클래스가 컴포넌트인 것은 아니다. 앱이 실행될 때 객체 생성부터 소멸까지
    `생명주기` 관리를 `개발자 코드`에서 한다면 `일반 클래스`이다. 이와 다르게 개발자가 만들기는
    했지만 `생명주기`를 `안드로이드 시스템`에서 관리한다면 `컴포넌트 시스템`이다.

- `컴포넌트의 종류`

    1. `액티비티` : 화면을 구성하는 컴포넌트이다. 앱의 화면을 안드로이드 폰에 출력하려면 액티비티를 만들어야 하며, 앱이 실행되면 액티비티에서 출력한 내용이 안드로이드 폰에 나온다.

    2. `서비스` : 백그라운드 작업을 하는 컴포넌트이다. 화면 출력 기능이 없으므로 서비스가 실행되더라도 화면에 출력되지 않는다. 서비스 컴포넌트는 화면과 상관없이 백그라운드에서 장시간 실행해야 할 업무를 담당한다.

    3. `컨텐츠 프로바이더` : 앱의 데이터를 공유하는 컴포넌트이다. 하나의 앱이 자신의 데이터를 다른 앱에 공유하려면 컨텐츠 프로바이더를 만들어야 하며, 다른 앱에서는 그 컨텐츠 프로바이더를 통해 데이터에 접근한다.

    4. `브로드캐스트 리시버` : 시스템 이벤트가 발생할 때 실행되게 하는 컴포넌트이다. 여기서 이벤트는 화면에서 발생하는 사용자 이벤트가 아니라, 시스템에서 발생하는 특정 상황을 의미한다. 예를 들면 부팅의 완료나 배터리 방전 같은 상황을 말한다.

- `컴포넌트`는 앱 안에서 `독립된 실행 단위`

    → 만약 Activity A, B가 있을 때, A → B로 화면을 전환하고자 한다면 안드로이드 시스템에 의뢰해서 Activity B를 불러오도록 해야 한다. 안드로이드에서 `컴포넌트`는 `서로 독립된 실행 단위`이기 때문에 `종속적으로 존재할 수 없다`. 예를 들면, A에서 B의 객체를 선언하여 화면을 전환하는 등의 종속적인 실행이 불가능 하다는 것이다.

    → 이와 비슷한 예로, 컴포넌트가 앱 내에서 독립해서 실행되는 특징 덕분에 앱의 실행 시점이 다양할 수 있다. 예를 들면, 사용자가 직접 앱을 실행하면 첫 화면에 Activity A가 나오도록 설정할 수 있고, 이와 다르게 사용자가 다른 특수한 방법으로 앱을 실행하면 Activity B가 먼저 나오도록 설정할 수도 있는 것이다.

    → 그래서 안드로이드 앱에는 `메인 함수`의 개념이 존재하지 않는다. `메인 함수`란 `앱의 단일 시작점`을 의미하는데, 안드로이드 앱은 실행 시점이 다양해서 메인 함수 개념이 존재하지 않는다.
